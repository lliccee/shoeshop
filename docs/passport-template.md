# Паспорт проекта

> Шаблон для заполнения на паре 5. Примеры в скобках — из эталона ShoeShop.
> Файл живёт в репозитории: `docs/passport.md`

## 1. Название проекта

"Shoeshop"

## 2. Проблема

«У элегантного магазина обуви каталог — на бумаге и в Excel: клиент не может посмотреть товар и оформить заказ, продавец путается в остатках».

## 3. Пользователи

• Клиент магазина — просматривает элегантный онлайн-каталог, фильтрует обувь по параметрам и оформляет заказ;
• Продавец-консультант — отслеживает новые заказы, актуализирует информацию о наличии размеров и выдает покупки;
• Администратор (владелец) — управляет ассортиментом, добавляет новые коллекции обуви и видит общую статистику продаж.

4. Цель проекта

Предоставить клиентам Shoshop возможность удобно выбирать обувь и оформлять заказы через эстетичный онлайн-каталог, а персоналу магазина — автоматически вести точный учет остатков в реальном времени.

5. Метрики успеха

• Время оформления заказа — клиент проходит путь от корзины до подтверждения покупки менее чем за 1.5 минуты;
• Поиск нужного размера — благодаря системе фильтров клиент находит подходящую пару обуви своего размера в каталоге за 3 клика или быстрее;
• Синхронизация склада — количество доступного товара на сайте уменьшается автоматически в течение 1 секунды после подтверждения заказа, исключая дублирующие продажи одной и той же пары.

6. Границы (что НЕ делаем)

• Реальный эквайринг — не подключаем настоящие платежные шлюзы (оплата имитируется учебным симулятором или выбирается «при получении»);
• Мобильная разработка — не создаем отдельные приложения для iOS/Android (делаем только адаптивный веб-сайт Shoshop);
• Службы доставки — не интегрируем API сторонних курьерских служб (СДЭК, Почта России), заказы выдаются исключительно самовывозом в шоуруме.

7. Риски

• Высокая нагрузка из-за обилия качественных фото обуви (сайт может долго грузиться) → оптимизируем и сжимаем изображения товаров, настраиваем «ленивую загрузку» (lazy loading);
• Сложность ручного наполнения премиального каталога → на старте ограничиваемся базой из 25–30 карточек реальных брендов, взятых из открытых каталогов;
• Нехватка времени на реализацию личного кабинета → жестко приоритизируем задачи: сначала делаем покупку в один клик без авторизации, а профиль клиента откладываем на финальный этап.
